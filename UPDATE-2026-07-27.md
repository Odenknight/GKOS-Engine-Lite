# Update — 2026-07-27

## What changed today

- **`368c304`** — Adopted the "engine-verbatim" CLI versioning rule (the
  `okf-lite` CLI's version now always matches the exact `gkos-engine` release
  it pins) and bumped the pin to `GKOS-Engine#v1.1.2`.
- **`b7c8319` (#8)** — Fixed the desktop build (Intel-mac target compiled on an
  arm64 runner) and pinned the desktop sidecar to engine v1.1.3.
- **`5f247db` — released as `v1.1.3`.** Caught the CLI up to
  `GKOS-Engine#v1.1.3` (bumped the engine pin, `package.json` version, and
  release tag together), re-resolved `package-lock.json` to the engine's exact
  commit SHA, and hardened the automated pin-bump workflow so a mid-run merge
  can no longer make it fail to push.

## Why

Two things converged today. First, GKOS-Engine itself released v1.1.3 (see
its own report) after a tag collision with a parallel run, so Engine-Lite's
pin needed to follow suit to stay "engine-verbatim." Second, a real bug was
found in the pin-bump automation while doing this: `npm ci` was silently
keeping the old engine version installed because the lockfile only recorded
the tag name (`v1.1.2`), not the resolved commit SHA — a tag string in a
lockfile doesn't force a fresh install if the tag itself hasn't moved
locally. That's now fixed by resolving to the actual SHA, and the automation
was additionally hardened to rebase before pushing so a same-window merge
can't cause a rejected push.

## Feature/functionality state now (v1.1.3)

- **CLI wrapper** (`okf-lite`, entry `bin/okf-lite.mjs`): thin wrapper around
  `gkos-engine`'s deterministic OKF23 commands, version pinned exactly to the
  engine release it ships (currently v1.1.3).
- **`okf-lite assist <task> <note.md>`**: opt-in, loopback-only assistance
  (`explain`, `improve`, `repair`, `find-links`, `check-privacy`) via the
  optional DSPy sidecar; every proposal is still validated by the canonical
  engine and unsafe/authoritative patches are rejected. All core commands work
  fully deterministically with the sidecar absent.
- **Desktop app** (Tauri 2 shell): bundles a 3D viewer window and supervises
  the engine sidecar; built/signed per platform including the Intel-mac cross
  build fixed today.
- **Pin-bump automation** (`.github/workflows/pin-bump.yml`): a
  `workflow_dispatch` job that adopts a given `gkos-engine` tag end-to-end —
  updates the pin, runs tests, commits, and tags — now hardened against both
  the lockfile SHA-resolution bug and merge-race push rejections.
